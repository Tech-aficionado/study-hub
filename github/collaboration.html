👥 Issues, Projects & Teams Intermediate

The tools for tracking work and managing who can do what.

1 Issues — bug tracking tied to code

An Issue is a trackable unit of work: a bug report, a feature request, a question. Issues support labels (bug, enhancement, good-first-issue), assignees, and milestones. Reference an issue from a commit or PR with #42 to auto-link them, and Fixes #42 in a PR description auto-closes it on merge.

2 Projects (boards)

A Kanban-style board (To Do / In Progress / Done) that organizes Issues and PRs visually. Can be scoped to one repo or span an entire organization's repos.

3 Discussions

A forum-style space for Q&A, announcements, and open-ended conversation that doesn't belong in a specific Issue — useful for "how do I..." questions that aren't bugs.

4 Teams and branch protection

Organizations group members into Teams with specific repo permissions (read/write/admin). Branch protection rules on an important branch like main can require: passing CI checks before merge, at least N approving reviews, no force-pushes, and up-to-date branches before merging.

💡 Branch protection is how teams enforce "nothing merges to main without review and green CI" — it's a setting, not a social agreement that people might forget.

5 CODEOWNERS — automatic review assignment

A CODEOWNERS file at the repo root maps file paths to usernames/teams who must review changes to those paths — GitHub auto-requests their review when a matching PR opens.

# .github/CODEOWNERS
/src/payments/   @finance-team
*.yml            @devops-lead
/docs/           @docs-team
