💚 Open Source & Licenses Intermediate

How to make your first contribution, and the licenses that decide what anyone may legally do with code.

1 Making your first contribution

  1. Find a project — look for the good first issue and help wanted labels.
  2. Read CONTRIBUTING.md and the Code of Conduct first — every project has its own rules.
  3. Comment on the issue to claim it, so you don't duplicate someone else's work.
  4. Fork → branch → change → PR (see the Forks page).
  5. Write a clear PR description linking the issue, and be responsive to review.
💡 Start small — a docs fix or a well-reported bug is a real, welcome contribution and teaches you a project's workflow before you tackle code.

2 The community health files

  • README.md — what the project is and how to use it.
  • CONTRIBUTING.md — how to set up, test and submit changes.
  • CODE_OF_CONDUCT.md — expected behaviour; makes a project welcoming.
  • LICENSE — the legal terms (below).
  • SECURITY.md — how to report vulnerabilities.

Put shared ones in a special .github repo in your org and they apply as defaults across all its repos.

3 Why a license is non-negotiable

Code with no license is "all rights reserved" by default — legally, nobody may use, copy, or modify it, even if it's public. If you want people to use your project, you must add a license. GitHub's "Add file → Choose a license template" picks one for you.

🛑 Public ≠ free to use. Without a LICENSE file, others technically cannot legally reuse your public code — add one deliberately.

4 The common licenses

LicenseTypeIn short
MITPermissiveDo almost anything; keep the copyright notice. The most popular.
Apache 2.0PermissiveLike MIT + an explicit patent grant. Good for larger projects.
BSDPermissiveSimilar to MIT, a few variants.
GPL v3CopyleftDerivatives must also be open-sourced under GPL.
AGPL v3Strong copyleftGPL + covers software used over a network (SaaS).

Permissive = minimal restrictions, reusable in closed-source. Copyleft = share-alike: anything built on it must stay open under the same terms.

5 Choosing and respecting licenses

  • Picking one? choosealicense.com walks you through it; MIT or Apache 2.0 are safe defaults for most projects.
  • Using a dependency? Check its license is compatible with how you ship — GPL in a closed-source product is a problem.
  • GitHub shows a repo's detected license in the About panel and the license file header.
