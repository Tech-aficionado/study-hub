🕹️ GitHub Flow Playground Interactive

A simulated GitHub + git. Run real commands against a modelled remote repo, local clone, pull requests and issues — all in your browser, nothing is sent anywhere.

1 How it works

Type commands in the terminal (or tap Run). Start with gh auth login, create a repo, then git clone and cd into it before running git commands. Issues and pull requests share one number sequence, so if issue #1 exists your first PR is #2. Branch protection on main blocks a merge until CI checks pass and there is 1 approval. The CI check comes from the workflow YAML pane — edit it, press Check workflow, and the simulated job either flags your mistakes or prints a run log and lets PR checks pass. A merge lands on the remote main, so your local main is behind until you git pull (watch the fast-forward). Press help anytime, use ↑/↓ for history and Tab to complete.

3 CI workflow (editable)

This is .github/workflows/ci.yml. The checker flags tabs, bad indentation, missing on/jobs/runs-on/steps, a step with neither uses nor run, unknown events, hard-coded secrets, and a missing permissions block when GITHUB_TOKEN writes.

Press "Check workflow" to validate and run it.

4 Guided challenges

    5 Break the YAML on purpose

    To see the checker work, try: delete the on: block, change runs-on to a tab-indented line, rename the event to pushh, add a step that is just - name: nothing, or paste a line like token: ghp_abcd1234abcd1234abcd. Then re-check — your PR's checks go failing and the merge is blocked until you fix it.
