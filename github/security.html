🔒 Security & Scanning Advanced

GitHub's built-in security stack: dependency alerts, secret scanning with push protection, code scanning, and a reporting policy.

1 The three layers of risk GitHub scans

2 Dependabot — alerts and updates

  • Dependabot alerts — notify you when a dependency you use has a known vulnerability (from the GitHub Advisory Database).
  • Dependabot security updates — automatically open a PR bumping that dependency to a fixed version.
  • Dependabot version updates — keep dependencies current on a schedule, via .github/dependabot.yml.
# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: "npm"
    directory: "/"
    schedule:
      interval: "weekly"
  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "weekly"
💡 Add a github-actions ecosystem entry too — it keeps the action versions in your workflows patched, which is a real supply-chain risk if left to drift.

3 Secret scanning + push protection

Secret scanning detects known credential formats (cloud keys, tokens) committed to a repo and alerts you. Push protection goes further — it blocks the push before the secret ever lands in history, with an override path that is logged.

🛑 If a real secret is ever committed, treat it as compromised and rotate/revoke it immediately. Rewriting history to remove it does NOT undo exposure — bots scrape public pushes within seconds, and the value may already be cached.

4 Code scanning with CodeQL

Code scanning runs static analysis on your source to find vulnerabilities and bugs — SQL injection, path traversal, unsafe deserialization — not just vulnerable dependencies. GitHub's engine is CodeQL, which treats code as a queryable database. Set it up with the default setup (one click) or an advanced workflow:

- uses: github/codeql-action/init@v3
  with:
    languages: javascript, python
- uses: github/codeql-action/analyze@v3

Findings appear in the Security → Code scanning tab and inline on the PR that introduced them. Third-party scanners can also upload results in the standard SARIF format.

5 SECURITY.md and private reporting

A SECURITY.md file tells people how to report a vulnerability responsibly — which versions are supported and where to send a report. Enable private vulnerability reporting so researchers can disclose privately via a form instead of opening a public issue.

# SECURITY.md
## Supported Versions
| Version | Supported |
| ------- | --------- |
| 2.x     | ✅        |
| 1.x     | ❌        |

## Reporting a Vulnerability
Use GitHub's private vulnerability reporting (Security tab),
or email security@example.com. We respond within 72 hours.
