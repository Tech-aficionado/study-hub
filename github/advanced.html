🛠️ CLI, Pages & Security Advanced

GitHub CLI, webhooks, static hosting, and the built-in security scanners.

1 GitHub CLI (gh)

The gh command-line tool lets you do most GitHub actions without leaving your terminal — create PRs, review them, manage issues, trigger workflows.

gh auth login
gh repo create my-project --public --source=. --push
gh pr create --title "Add feature" --body "Description here"
gh pr list
gh pr merge 42 --squash
gh issue create --title "Bug: login fails"
gh run list                     # recent Actions workflow runs
gh run watch                    # live-tail a running workflow

2 Webhooks

A webhook is a URL you register that GitHub POSTs an event payload to whenever something happens (push, PR opened, issue commented). This is how external tools (Slack notifications, deploy triggers, custom bots) react to repo activity in real time, without polling.

3 GitHub Pages

Free static site hosting directly from a repo. Point it at a branch (commonly gh-pages or main's /docs folder) in Settings → Pages, and GitHub serves it at username.github.io/repo.

4 Packages

GitHub Packages hosts your own package registry (npm, Docker images, Maven, NuGet) tied to your repos and permissions — useful for private packages shared within an org without a separate registry service.

5 Built-in security features

  • Dependabot — automatically opens PRs to bump dependencies with known vulnerabilities.
  • Secret scanning — detects accidentally committed API keys/tokens and alerts you (and can block the push).
  • Code scanning (CodeQL) — static analysis that finds security vulnerabilities in your code itself, not just dependencies.
🛑 If secret scanning flags a leaked credential, treat it as compromised immediately — rotate/revoke it. Removing it from Git history later does NOT undo the exposure; it may already be cached/scraped.
