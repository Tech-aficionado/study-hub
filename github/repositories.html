🗂️ Repositories & Visibility Beginner

What lives inside a repository, the three visibility levels, and the anatomy of the repo page.

1 What a repository actually contains

A repository ("repo") is a project folder that GitHub hosts — but it is more than files. It bundles the full Git history (every commit, branch and tag), plus GitHub-only metadata: issues, pull requests, releases, settings, collaborators and Actions runs. When you clone a repo you get the files and the whole history; the issues and PRs stay on GitHub.

2 The three visibility levels

  • Public — visible and clonable by anyone; the basis of open source. People still cannot push without being granted write access.
  • Private — hidden from everyone except you and the collaborators/teams you invite.
  • Internal — an Enterprise option: visible to every member of your organisation but not the public. Good for shared internal tooling.
⚠️ Changing a repo from private to public exposes its entire history. A secret committed long ago and "deleted" later is still in the history — rotate it before going public.

3 Creating a repo and connecting a local project

# Option A: start on GitHub (New repository), then connect your local folder
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/user/repo.git
git push -u origin main

# Option B: one command with the CLI (creates + pushes)
gh repo create my-project --public --source=. --push

The -u on the first push sets the upstream so later you can just type git push / git pull.

4 Description, topics and the About panel

The right-hand About panel sets a one-line description, a website link and topics — tags like machine-learning or cli-tool that make the repo discoverable in GitHub search and topic pages. A clear description plus 3–5 relevant topics dramatically improves how people find your project.

5 Archiving, transferring and deleting

  • Archive — makes a repo read-only to signal it is no longer maintained, without losing it. Reversible.
  • Transfer — hand ownership to another user or org; redirects keep old links working.
  • Delete — permanent. GitHub makes you type the full repo name to confirm, because there is no undo.
