⚙️ GitHub Actions Intermediate

Run code automatically whenever something happens in your repo — tests, builds, deployments.

1 What Actions actually is

GitHub Actions is CI/CD built directly into GitHub: you write a workflow file in YAML, GitHub watches for the events you specify (push, pull request, a schedule), and when one fires, it spins up a fresh virtual machine (a "runner") to execute your steps.

2 Anatomy of a workflow file

# .github/workflows/ci.yml
name: CI
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm install
      - run: npm test
  • on — the trigger: push, pull_request, schedule (cron), or manual (workflow_dispatch).
  • jobs — one or more independent units of work, each running on its own fresh runner by default.
  • runs-on — which OS/runner image: ubuntu-latest, windows-latest, macos-latest.
  • steps — the sequence inside a job: either a reusable uses: action from the Marketplace, or a raw run: shell command.

3 Pipeline flow

⚠️ Each job runs on a brand-new, clean VM by default. Nothing persists between jobs unless you explicitly use actions/cache or upload/download artifacts.

4 Secrets

Never hardcode credentials in a workflow file (it's committed, public if the repo is public). Store them in Settings → Secrets and Variables → Actions, then reference as ${{ secrets.MY_API_KEY }}.
