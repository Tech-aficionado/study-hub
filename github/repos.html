📦 Repos & Forking Beginner

Creating repos, forking someone else's, and the files every good repo has.

1 Creating a repository

On GitHub, click "New repository," give it a name, choose Public or Private, and optionally initialize it with a README, .gitignore, and license. Then connect it to your local Git repo:

git remote add origin https://github.com/user/repo.git
git branch -M main
git push -u origin main
Public repos are visible and clonable by anyone — great for open source. Private repos are visible only to you and people you explicitly invite.

2 Forking: your own copy of someone else's repo

A fork creates a full copy of a repository under YOUR account on GitHub. This is the standard way to contribute to a project you don't have write access to — you fork it, make changes in your copy, then open a Pull Request asking the original project to pull your changes in.

# After clicking "Fork" on GitHub, clone YOUR fork:
git clone https://github.com/your-username/repo.git

# Add the original repo as a second remote, conventionally named "upstream"
git remote add upstream https://github.com/original-owner/repo.git

# Periodically sync your fork with the original project's new changes
git fetch upstream
git merge upstream/main

3 The files every good repo has

  • README.md — the front door. What the project does, how to install/run it, how to contribute.
  • .gitignore — files Git should never track (build output, secrets, dependencies).
  • LICENSE — legally defines what others are allowed to do with your code. No license = all rights reserved by default.
  • CONTRIBUTING.md — rules and process for outside contributors on bigger projects.

4 Repo visibility and topics

Repository Settings let you control visibility (public/private/internal for orgs), add topics (tags that help discovery, e.g. "machine-learning", "cli-tool"), and set a description that shows up in search results.
