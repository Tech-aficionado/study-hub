🌐 GitHub Pages Intermediate

Free static-site hosting straight from a repository — docs, portfolios, project landing pages.

1 What Pages is

GitHub Pages serves static files (HTML, CSS, JS, images) from a repo over HTTPS, at no cost. It is ideal for documentation sites, personal portfolios, project pages and anything that doesn't need a server. It cannot run server-side code — no databases or back-end logic — only static assets and client-side JavaScript.

⚠️ A project site is served under a sub-path (/repo/). Absolute asset links like /style.css break — use relative links or set the correct base path in your build tool.

3 Two ways to publish

  • Deploy from a branch — point Pages at a branch (and optionally the /docs folder). GitHub serves whatever is there. Simple for hand-written HTML.
  • GitHub Actions — a workflow builds and deploys (see "Deploy with Actions"). Required when you have a build step (Vite, Jekyll, Hugo, Next export).

4 Jekyll and the .nojekyll trick

Pages runs Jekyll by default, which has one surprising side effect: it ignores files and folders starting with an underscore (_next, _app). If your framework uses those, add an empty .nojekyll file at the site root to disable Jekyll processing and serve files as-is.

5 Custom domains and HTTPS

Point your own domain at Pages by adding a CNAME record (for www) or A/ALIAS records (for the apex) at your DNS provider, then set the domain in Settings → Pages. GitHub provisions a free TLS certificate; tick Enforce HTTPS once it's ready.

💡 A 404.html at the site root is served for unknown paths — useful for single-page apps that need all routes to fall back to one entry point.
