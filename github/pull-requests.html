🔀 Pull Requests Intermediate

The structured, reviewable way to propose a change — the heart of GitHub collaboration.

1 The fork → branch → PR → merge flow

2 Opening a PR

git switch -c feature-login
# ...make changes, commit...
git push -u origin feature-login
# Then on GitHub: click "Compare & pull request" — write a clear title and description
💡 A good PR description answers: WHAT changed, WHY it was needed, and HOW to test it. Link the issue it fixes with "Fixes #42" — GitHub auto-closes that issue when the PR merges.

3 Draft PRs and code review

A Draft PR signals "work in progress, not ready for review yet" — useful for getting early CI feedback or showing direction without requesting review time. Reviewers leave inline comments on specific lines, suggest changes, and formally Approve or Request Changes.

4 Merge strategies — the three options

StrategyResultWhen to use
Merge commitKeeps every individual commit + adds a merge commitWhen commit-level history matters
Squash and mergeCombines ALL PR commits into one clean commitMost common — keeps main branch history tidy
Rebase and mergeReplays commits individually, no merge commitWhen you want linear history but keep each commit separate
