🪜 CTEs & Recursive Queries Advanced

WITH clauses that name a subquery for readability — and recursive CTEs that walk hierarchies and generate series.

1 A Common Table Expression (CTE)

A CTE is a named, temporary result defined with WITH at the top of a query. It makes complex queries read top-to-bottom instead of inside-out.

WITH order_totals AS (
  SELECT order_id, SUM(quantity * unit_price) AS total
  FROM order_items
  GROUP BY order_id
)
SELECT * FROM order_totals
WHERE total > 100
ORDER BY total DESC;
💡 The same thing can be a subquery in FROM, but a CTE reads better and can be referenced multiple times in the same query. You can chain several: WITH a AS (…), b AS (… FROM a …) SELECT … FROM b;

2 Multiple CTEs chained together

WITH per_customer AS (
  SELECT customer_id, COUNT(*) AS orders
  FROM orders GROUP BY customer_id
),
ranked AS (
  SELECT customer_id, orders,
         RANK() OVER (ORDER BY orders DESC) AS rk
  FROM per_customer
)
SELECT * FROM ranked WHERE rk <= 5;   -- top 5 customers by order count

3 Recursive CTE — anatomy

A recursive CTE has two parts combined with UNION ALL: an anchor (the starting rows) and a recursive member that references the CTE itself, running until it produces no new rows.

WITH RECURSIVE nums(n) AS (
  SELECT 1                       -- anchor: the first row
  UNION ALL
  SELECT n + 1 FROM nums WHERE n < 10   -- recursive step; the WHERE is the stop condition
)
SELECT n FROM nums;              -- 1,2,3,…,10
🛑 Always give the recursive member a terminating condition (WHERE n < 10). Without one it loops forever — PostgreSQL will spin until it runs out of memory. SQLite caps nothing by default either.

4 Recursive CTE — walking an org chart

The real power: traversing a parent/child hierarchy (employees → managers, categories → subcategories, threaded comments) to any depth.

WITH RECURSIVE chain AS (
  SELECT id, name, manager_id, 1 AS level
  FROM employees
  WHERE manager_id IS NULL           -- anchor: the top of the tree (CEO)
  UNION ALL
  SELECT e.id, e.name, e.manager_id, c.level + 1
  FROM employees e
  JOIN chain c ON e.manager_id = c.id   -- attach each person under their manager
)
SELECT level, name FROM chain ORDER BY level, name;
💡 The RECURSIVE keyword is required in PostgreSQL, SQLite, and SQL standard. MySQL (8.0+) also requires WITH RECURSIVE. Older MySQL (5.x) had no CTEs at all — you emulated hierarchies with application code or stored procedures.

5 When NOT to use a CTE

CTEs are about readability, not always speed. In older PostgreSQL (< 12) a CTE was an "optimization fence" — materialised and never merged into the outer query, sometimes slower than an equivalent subquery. PostgreSQL 12+ inlines non-recursive CTEs by default (use AS MATERIALIZED to force the old behaviour). For a one-off simple filter, a plain subquery or WHERE is fine.
