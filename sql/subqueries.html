📦 Subqueries Intermediate

A query inside a query — scalar, IN, EXISTS, and the correlated subquery that runs once per outer row.

1 Scalar subquery — returns a single value

SELECT name, price
FROM products
WHERE price > (SELECT AVG(price) FROM products);
-- The inner query returns ONE number; the outer compares each row to it

-- A scalar subquery can also appear in the SELECT list:
SELECT name, (SELECT COUNT(*) FROM orders) AS total_orders FROM customers;
⚠️ A scalar subquery must return at most one row and one column. If it returns multiple rows where one value is expected, the engine raises an error ("more than one row returned by a subquery used as an expression").

2 IN subquery — membership in a list

SELECT name FROM customers
WHERE id IN (SELECT customer_id FROM orders WHERE status = 'cancelled');
-- "customers who have at least one cancelled order"
🛑 NOT IN + a subquery that can yield NULL is dangerous: a single NULL in the inner result makes NOT IN return nothing. Use NOT EXISTS (below) whenever NULLs are possible.

3 EXISTS — "is there at least one match?"

SELECT c.name
FROM customers c
WHERE EXISTS (
  SELECT 1 FROM orders o WHERE o.customer_id = c.id
);
-- EXISTS stops at the first match — it only cares IF a row exists, not what's in it

-- The NULL-safe anti-join:
SELECT c.name FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.customer_id = c.id);  -- never ordered
💡 Inside EXISTS the SELECT list is irrelevant — SELECT 1, SELECT *, anything works, because EXISTS only checks row presence. SELECT 1 is the conventional, clear choice.

4 Correlated subquery — runs once per outer row

A correlated subquery references a column from the outer query, so it can't be run once up front — it re-evaluates for every outer row.

SELECT c.name,
  (SELECT COUNT(*) FROM orders o WHERE o.customer_id = c.id) AS order_count
FROM customers c;
-- c.id in the inner query ties it to the current outer row
⚠️ Correlated subqueries can be slow — they re-run per row (O(n) executions). A JOIN … GROUP BY or a window function often computes the same thing in one pass. Compare both when performance matters, but modern optimisers sometimes rewrite correlated subqueries into joins automatically.

5 Subquery in FROM (derived table)

SELECT tier, COUNT(*) AS n
FROM (
  SELECT CASE WHEN price >= 100 THEN 'premium' ELSE 'standard' END AS tier
  FROM products
) AS classified
GROUP BY tier;
-- Treat a subquery's result as a temporary table to query further
💡 A derived table in FROM must be aliased (here, AS classified) in most dialects. When a derived table gets reused or deeply nested, a CTE (next page) is usually clearer.
