🧷 Joins In Depth Intermediate

Every join type — INNER, LEFT, RIGHT, FULL, CROSS, SELF — with both the Venn picture and what actually happens at the row level.

1 The two tables we'll join

Throughout, picture a small customers table and an orders table. A join matches rows where orders.customer_id = customers.id.

2 INNER JOIN — intersection

SELECT c.name, o.id AS order_id
FROM customers c
INNER JOIN orders o ON o.customer_id = c.id;

Only rows that match on both sides. Carla (no orders) and order 12 (no matching customer) both disappear. Result: Ana×2 orders, Ben×0 would also disappear if Ben had no orders.

3 LEFT JOIN — all of the left, matched or not

SELECT c.name, o.id AS order_id
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id;

Every customer appears. Carla has no order, so order_id is NULL for her.

💡 "Anti-join" — find rows with NO match by keeping the LEFT JOIN rows where the right side is NULL: … LEFT JOIN orders o ON … WHERE o.id IS NULL finds customers who never ordered.

4 RIGHT JOIN and FULL OUTER JOIN

RIGHT JOIN keeps every row from the right table. It's just a mirror of LEFT JOIN — most people swap the table order and use LEFT instead, as it reads more naturally.

FULL OUTER JOIN keeps everything from both sides, matching where possible and NULL-filling where not. Perfect for reconciling two datasets ("what's in A but not B, and vice-versa").

🛑 MySQL has no FULL OUTER JOIN. Emulate it with LEFT JOIN … UNION … RIGHT JOIN …. PostgreSQL, SQLite (3.39+), SQL Server, and Oracle support it natively.

5 CROSS JOIN — every combination

SELECT s.size, col.color
FROM sizes s
CROSS JOIN colors col;    -- every size paired with every color (Cartesian product)

No ON clause — it pairs every left row with every right row. 3 sizes × 4 colors = 12 rows. Useful for generating grids/combinations.

⚠️ An accidental cross join is a classic bug: forget the ON condition (or write FROM a, b with no join predicate in WHERE) and you get the full Cartesian product — millions of rows from two modest tables.

6 SELF JOIN — a table joined to itself

SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m ON m.id = e.manager_id;
-- Alias the SAME table twice: 'e' as the worker, 'm' as their manager

You alias one table as two logical copies. Essential for hierarchies (employee → manager), finding pairs, or comparing rows within the same table.

7 USING and NATURAL JOIN

-- USING: shorthand when both sides share the column NAME
SELECT * FROM orders JOIN customers USING (customer_id);  -- needs a 'customer_id' in both

-- NATURAL JOIN: auto-joins on ALL same-named columns — avoid, it's fragile
SELECT * FROM orders NATURAL JOIN customers;
⚠️ Avoid NATURAL JOIN in real code: adding a same-named column later (like created_at in both tables) silently changes the join condition and breaks the query. Always write an explicit ON.
