🏛️ CREATE TABLE & Constraints Intermediate

Defining tables and the guardrails that keep bad data out — PK, FK with ON DELETE, UNIQUE, CHECK, NOT NULL, DEFAULT.

1 A fully-constrained table

-- PostgreSQL
CREATE TABLE customers (
  id         SERIAL PRIMARY KEY,                 -- auto-incrementing unique id
  email      VARCHAR(255) NOT NULL UNIQUE,       -- required and no duplicates
  name       VARCHAR(120) NOT NULL,
  age        INTEGER CHECK (age >= 0),           -- value rule enforced on write
  country    CHAR(2) NOT NULL DEFAULT 'US',      -- value used when none supplied
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
💡 Constraints are the database defending its own correctness. A bug in application code can't insert a negative age or a duplicate email — the engine rejects it, every time, for every client.

2 The five everyday constraints

ConstraintGuarantees
PRIMARY KEYUnique + NOT NULL; the row's identity. One per table (can span columns).
NOT NULLThe column must always have a value.
UNIQUENo two rows share this value (e.g. email). Allows multiple NULLs in most engines.
CHECK (expr)A custom rule — price >= 0, status IN ('a','b').
DEFAULT valValue inserted when the column is omitted.
⚠️ MySQL ignored CHECK constraints before version 8.0.16 — it parsed them but didn't enforce them. On modern MySQL (8.0.16+) they are enforced. SQLite and PostgreSQL have always enforced CHECK.

3 Foreign keys and referential actions

A foreign key says "this column's value must exist as a primary key in another table." The ON DELETE / ON UPDATE clauses decide what happens to the children when the parent row is removed or changed.

CREATE TABLE orders (
  id          SERIAL PRIMARY KEY,
  customer_id INTEGER NOT NULL,
  total       NUMERIC(10,2) NOT NULL,
  FOREIGN KEY (customer_id) REFERENCES customers(id)
    ON DELETE CASCADE        -- delete a customer → their orders vanish too
    ON UPDATE CASCADE
);
ON DELETE actionEffect when the parent row is deleted
CASCADEDelete the child rows too.
RESTRICT / NO ACTIONBlock the delete if children exist (the safe default).
SET NULLSet the child's FK column to NULL (must be nullable).
SET DEFAULTSet the child's FK to its DEFAULT value.
🛑 SQLite does NOT enforce foreign keys unless you turn them on per connection: PRAGMA foreign_keys = ON;. It's off by default for historical compatibility — a frequent "my CASCADE isn't working" surprise.

4 Composite keys and table-level constraints

A primary (or unique) key can span several columns — useful for junction tables in many-to-many relationships.

CREATE TABLE enrollments (
  student_id INTEGER NOT NULL REFERENCES students(id),
  course_id  INTEGER NOT NULL REFERENCES courses(id),
  grade      CHAR(1),
  PRIMARY KEY (student_id, course_id)   -- a student can't enroll in the same course twice
);

5 ALTER and DROP — changing structure later

ALTER TABLE customers ADD COLUMN phone VARCHAR(20);
ALTER TABLE customers ADD CONSTRAINT uq_phone UNIQUE (phone);
ALTER TABLE customers DROP COLUMN phone;

DROP TABLE IF EXISTS customers;    -- removes the table AND all its data
⚠️ SQLite's ALTER TABLE is limited — it can rename/add columns and (since 3.35) drop a column, but can't add many constraints to an existing table. The classic workaround is "create a new table, copy, drop, rename." PostgreSQL and MySQL have far richer ALTER support.
