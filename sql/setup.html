🧰 Setup & Tools Beginner

Get a database running on your machine — and know when to reach for which one.

1 Which database should you learn on?

EngineWhat it isReach for it when
SQLiteA whole database in a single file, no server processLearning, mobile apps, small sites, tests, local tooling. This course's playground uses it.
PostgreSQLPowerful open-source server, strict standards complianceSerious production apps, complex queries, JSON, extensions (PostGIS)
MySQL / MariaDBOpen-source server, huge web ecosystemClassic LAMP/web stacks, WordPress, read-heavy workloads
💡 Start with SQLite to learn the language with zero setup. The core SQL (SELECT, JOIN, GROUP BY, window functions) is nearly identical across all three — only edge syntax differs, and this course flags every difference.

2 SQLite — nothing to install, really

SQLite ships with macOS, most Linux distros, Python, and many languages. A database is just a file you create.

# Open (or create) a database file and get an interactive prompt
sqlite3 shop.db

# Inside the sqlite3 prompt:
sqlite> CREATE TABLE items (id INTEGER PRIMARY KEY, name TEXT);
sqlite> INSERT INTO items (name) VALUES ('Widget');
sqlite> SELECT * FROM items;
sqlite> .tables        -- list tables (dot-commands are SQLite-specific)
sqlite> .schema items  -- show a table's CREATE statement
sqlite> .quit
⚠️ Dot-commands (.tables, .schema, .mode) are features of the sqlite3 command-line shell, NOT SQL. They won't work from application code — there you query sqlite_master instead.

3 PostgreSQL — install and connect

# macOS (Homebrew)
brew install postgresql@16 && brew services start postgresql@16

# Ubuntu/Debian
sudo apt install postgresql

# Connect with the psql client
psql -U postgres -d postgres
postgres=# CREATE DATABASE shop;
postgres=# \c shop        -- connect to the shop database
shop=# \dt                -- list tables
shop=# \d items           -- describe a table
shop=# \q                 -- quit
Docker is often the fastest path: docker run --name pg -e POSTGRES_PASSWORD=secret -p 5432:5432 -d postgres:16 gives you a throwaway server in seconds.

4 MySQL — install and connect

# macOS (Homebrew)
brew install mysql && brew services start mysql

# Connect with the mysql client
mysql -u root -p
mysql> CREATE DATABASE shop;
mysql> USE shop;
mysql> SHOW TABLES;
mysql> DESCRIBE items;
mysql> EXIT;
⚠️ MySQL's meta-commands (SHOW TABLES, DESCRIBE, USE) are real SQL extensions, unlike SQLite's dot-commands or Postgres's backslash commands. Each engine's "list my tables" verb is different — a classic source of confusion when switching.

5 GUI clients and the standard way to list tables

GUI tools make exploration easier: DBeaver (works with every engine), pgAdmin (Postgres), TablePlus, DataGrip, and the SQLite VS Code extensions.

The portable, SQL-standard way to inspect a schema is the information_schema views (PostgreSQL & MySQL):

SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public';   -- 'public' in Postgres; your db name in MySQL

SQLite has no information_schema; it uses a built-in table instead:

SELECT name FROM sqlite_master WHERE type = 'table';   -- SQLite
