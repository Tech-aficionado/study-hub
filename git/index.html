🌿 What is Git? Beginner

The tool that remembers every version of your code, forever.

1 The problem Git solves

Without version control, "final_v2_REAL_fixed.docx" is a real folder you've probably seen. The moment more than one person touches a project — or you just want to try something risky without breaking what works — you need a system that remembers every change, who made it, and lets you go back in time if needed.

Git is a distributed version control system. "Distributed" is the key word: every clone of a Git repository has the FULL history, not just a pointer to a central server. You can commit, branch, and view history completely offline — syncing with others (like on GitHub) is a separate, later step.

💡 Git doesn't store "files" the way you think — it stores snapshots. Every commit is a complete picture of your whole project at that moment, not a diff. Git is just extremely good at storing those snapshots efficiently (unchanged files are stored once, re-linked by reference).

2 The three trees: Working Directory, Staging Area, Repository

This is the single most confusing part of Git for beginners, and once it clicks, everything else makes sense. Git tracks your project through three distinct areas:

  • Working Directory — the files you see and edit in your editor right now.
  • Staging Area (index) — a holding pen. git add moves a change here, saying "include this in the next commit."
  • Repository — the permanent, committed history, stored in the hidden .git folder. git commit takes everything staged and seals it as a permanent snapshot.
Why a separate staging step? It lets you commit only PART of what you changed — e.g. you fixed two unrelated bugs in one editing session, but want two clean, separate commits.

3 Why Git over "just using folders" or Google Docs-style history

  • Branching is cheap — you can try a risky idea in seconds, and throw it away with zero cost if it doesn't work.
  • Full history, always local — no internet needed to see who changed what and when.
  • Merging is a first-class operation — Git is built to combine two people's parallel work automatically, not just prevent them from touching the same file.
  • It's the industry standard — GitHub, GitLab, Bitbucket, and nearly every CI/CD pipeline assume Git underneath.
