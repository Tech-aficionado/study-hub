1 Cherry-pick: grab one specific commit

Sometimes you need just ONE commit from another branch, not the whole thing. cherry-pick replays a single commit onto your current branch.

git cherry-pick <commit-hash>
# Applies just that one commit's changes onto your current branch

2 Interactive rebase: rewriting your own history

rebase -i opens an editable list of your recent commits, letting you squash messy "wip" commits into one clean commit, reorder them, edit messages, or drop ones you don't want — before you ever push.

git rebase -i HEAD~5
# Opens an editor listing your last 5 commits, each with a word in front: pick

# Change the word in front of a commit:
pick    # keep as-is
squash  # combine into the commit above
reword  # keep the changes, edit the message
drop    # remove this commit entirely
💡 "Squash your WIP commits before opening a PR" means exactly this — turning 12 messy "fix typo", "wip", "actually fix it" commits into one clean, reviewable commit.

3 git bisect: binary-search for the commit that broke something

A bug appeared somewhere in the last 200 commits and you have no idea which one. bisect does a binary search: Git checks out a commit, you test it and say good/bad, and it narrows down to the exact culprit in log₂(200) ≈ 8 steps.

git bisect start
git bisect bad                 # current commit is broken
git bisect good <old-hash>     # this older commit was fine
# Git checks out a commit in between — you test it, then:
git bisect good   # or
git bisect bad
# Repeat until Git names the exact first-bad commit
git bisect reset               # return to where you started

4 Submodules: a repo inside a repo

A submodule links another Git repository as a subfolder, pinned to a specific commit. Common for shared libraries that need to stay independently versioned.

git submodule add https://github.com/user/lib.git libs/lib
git submodule update --init --recursive
# When cloning a repo WITH submodules, use:
git clone --recurse-submodules <url>
⚠️ Submodules are notoriously fiddly — many teams prefer a package manager (npm, pip) or a monorepo instead, unless there's a strong reason for a true separate-repo link.

5 Git hooks: automation on events

Scripts in .git/hooks/ that run automatically on events like committing or pushing — e.g. running a linter before every commit so broken code never gets committed.

# .git/hooks/pre-commit  (make it executable: chmod +x)
#!/bin/sh
npm run lint || exit 1
# If lint fails (non-zero exit), the commit is blocked
Hooks live in .git/hooks/, which is NOT committed to the repo by default — tools like Husky exist to make hooks shareable across a team.
