🏷️ Tags & Releases Intermediate

Permanent, named markers for the commits that matter — your v1.0.0, v2.3.1 and release points.

1 What a tag is

A tag is a fixed label on a specific commit that never moves. Branches advance as you commit; tags stay put. They mark release points — v1.0.0, v2.3.1 — so you can always check out exactly what shipped.

2 Lightweight vs annotated tags

Two kinds. A lightweight tag is just a name pointing at a commit — like a branch that never moves. An annotated tag is a full object storing a tagger, date, message, and can be GPG-signed. Use annotated tags for releases.

# Lightweight — just a pointer, no metadata
git tag v1.0.0-rc1

# Annotated — stores tagger, date, message (the right choice for releases)
git tag -a v1.0.0 -m "First stable release"

# Signed annotated tag (cryptographically verifies who created it)
git tag -s v1.0.0 -m "First stable release"

# Tag an OLD commit after the fact
git tag -a v0.9.0 9fceb02 -m "Beta release"

3 Listing, inspecting and pushing tags

git tag                     # list all tags
git tag -l "v1.*"           # filter with a pattern
git show v1.0.0             # tag metadata + the commit it points to

# Tags are NOT pushed by default — you must push them explicitly
git push origin v1.0.0       # push one tag
git push origin --tags       # push all tags

git push origin --delete v1.0.0   # delete a tag on the remote
git tag -d v1.0.0                 # delete a tag locally
⚠️ The classic gotcha: you git tag a release, run git push, and the tag doesn't appear on the remote. Plain push never sends tags — you need git push origin <tag> or --tags.

4 Semantic Versioning (SemVer)

The near-universal convention for release tags is MAJOR.MINOR.PATCH, e.g. 2.4.1. Each number signals the kind of change so consumers know whether an upgrade is safe.

PartBump when…Example
MAJORYou make a breaking change1.9.0 → 2.0.0
MINORYou add functionality, backward-compatible2.0.0 → 2.1.0
PATCHYou fix a bug, backward-compatible2.1.0 → 2.1.1
💡 Pre-release suffixes communicate stability: 2.0.0-alpha.1, 2.0.0-beta.3, 2.0.0-rc.1 (release candidate). A leading 0.x.y signals "still unstable, anything may change."

5 Checking out and describing by tag

git checkout v1.0.0
# Puts you at exactly what shipped as v1.0.0 (detached HEAD — read-only look)
git switch -c hotfix-1.0.1 v1.0.0
# ...or branch off the tag to make a patch release

git describe --tags
# Human-readable version of your current commit, e.g. v1.1.0-14-g2414721
# = 14 commits after v1.1.0, at commit 2414721 — great for build version strings
