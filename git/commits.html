📜 Commits & History Beginner

What a commit really is, how to read history like a detective, and how to write messages your team will thank you for.

1 What a commit actually is

A commit is a complete snapshot of your tracked files at one moment, plus metadata: author, timestamp, a message, and a pointer to its parent commit (the one before it). That parent pointer is what links commits into a history you can walk backward.

The commit ID (e.g. g7h8i9...) is a 40-character SHA-1 hash of the commit's content. You almost always use just the first 7 characters — enough to be unique in most repos.

2 Writing a good commit message

The widely-followed convention: a short imperative summary (≤ 50 chars), a blank line, then a body explaining the why. "Imperative" means it completes the sentence "If applied, this commit will…".

3 Reading history: git log and its best options

git log --oneline
# One commit per line: short hash + summary. The everyday view.

git log --oneline --graph --all --decorate
# ASCII graph of ALL branches, with branch/tag labels — the power view

git log -5
# Just the last 5 commits

git log --stat
# Each commit plus which files changed and how many lines

git log -p
# Full patch (diff) for each commit

git log --author="Ada" --since="2 weeks ago"
# Filter by author and time

git log -S"functionName"
# "Pickaxe": commits that added or removed that string — great for "when did this appear?"

git log main..feature
# Commits on feature that are NOT yet on main

4 Inspecting one commit: git show

git show g7h8i9
# The full detail of one commit: metadata + the diff it introduced

git show HEAD
git show HEAD~2        # two commits before the current tip
git show HEAD~2:app.js # how app.js looked at that commit
Two ways to walk backward: HEAD~2 means "2 first-parents back" (what you want 99% of the time). HEAD^2 means "the 2nd parent" and only matters on merge commits, which have two parents.

5 git commit --amend — fix your last commit

Forgot a file, or made a typo in the message? --amend replaces the most recent commit with a new one that includes your fix. It does not add a second commit — it rewrites the last one.

git commit --amend -m "Corrected message"
# Rewrites the last commit's message

git add forgotten-file.js
git commit --amend --no-edit
# Adds the file to the last commit, keeps the same message
⚠️ --amend creates a NEW commit with a new hash. Never amend a commit you've already pushed to a shared branch — you'd be rewriting history others may already have. Amend only your own un-pushed work.

6 Blame & who-changed-what

git blame app.js
# Annotate every line with the commit, author and date that last touched it

git blame -L 40,60 app.js
# Just lines 40–60 — much easier to read
💡 "Blame" sounds accusatory but it's really a time-travel tool: it tells you which commit introduced a line, so you can git show that commit and read why the change was made.
