🚫 .gitignore & .gitattributes Intermediate

Keep junk out of the repo, and make line endings & diffs behave the same for everyone on the team.

1 What belongs in .gitignore

Not everything should be versioned: build output, dependency folders, secrets, editor and OS cruft. A .gitignore file lists patterns Git will never track. Commit it so the whole team shares the same rules.

# .gitignore
node_modules/        # dependencies — reinstallable from package.json
dist/                # build output
*.log                # all log files
.env                 # secrets — NEVER commit these
.DS_Store            # macOS folder metadata
Thumbs.db            # Windows thumbnail cache
.idea/               # JetBrains editor settings
*.tmp
💡 Don't write ignore files from scratch — GitHub maintains language/tool templates at github/gitignore. Start from the one for your stack (Node, Python, etc.) and tweak.

2 Pattern syntax

PatternMatches
*.logAny file ending in .log, anywhere
build/A directory named build (trailing slash = dir only)
/config.jsonconfig.json only at the repo root (leading slash)
docs/**/*.pdfPDFs at any depth under docs/
!important.logUn-ignore (negate) — keep this one despite *.log
temp?temp + one character (temp1, tempA)
Order matters with negation: a ! rule only works if the file wasn't already excluded by a parent-directory rule. You can't re-include a file if its whole directory is ignored.

3 The "already tracked" trap

Adding a pattern to .gitignore does not stop tracking a file Git already tracks. Ignore rules only apply to untracked files. To stop tracking something you committed by mistake:

git rm --cached .env
# Stop tracking .env (keeps your local copy); now .gitignore takes effect
git commit -m "Stop tracking .env, add to .gitignore"

# Clear and re-apply ignore rules across the whole tree at once:
git rm -r --cached .
git add .
git commit -m "Apply .gitignore to already-tracked files"
🛑 If you committed a real secret (API key, password), removing it from tracking is not enough — it still lives in history. You must rotate/revoke the secret AND scrub history (git filter-repo or BFG). Treat any committed secret as compromised.

4 Other ignore mechanisms

git check-ignore -v path/to/file
# Which rule (and which file) is causing this path to be ignored? Great for debugging

# Global ignore for YOUR machine only (editor files, OS cruft)
git config --global core.excludesFile ~/.gitignore_global

# Per-repo private ignores NOT shared with the team:
.git/info/exclude

5 .gitattributes — team-wide file behaviour

Where .gitignore says what to skip, .gitattributes says how to treat files Git does track. It's committed, so it enforces consistent line endings, diffs and merge behaviour for everyone — the robust fix for the Windows CRLF problem.

# .gitattributes
* text=auto                 # normalise line endings: LF in repo, native on checkout
*.sh    text eol=lf         # shell scripts ALWAYS LF, even on Windows
*.bat   text eol=crlf       # batch files ALWAYS CRLF
*.png   binary              # never try to diff/merge or convert — treat as binary
*.lock  -diff               # don't show diffs for lockfiles (noisy, machine-generated)
*.pdf   diff=astextplain    # use a custom textconv to show readable diffs
💡 Committing * text=auto in .gitattributes is better than relying on each developer's core.autocrlf — the rule travels with the repo, so a new teammate gets correct line endings without configuring anything.
