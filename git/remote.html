☁️ Remotes & Collaboration Intermediate

Your local repo plus a copy living somewhere else (usually GitHub) — how they stay in sync.

1 What a "remote" is

A remote is just a nickname for a URL pointing at another copy of your repository — usually on GitHub, GitLab, or a company server. The default remote name is origin, but it's just a convention, not a special keyword.

git remote -v
# Lists all remotes and their URLs

git remote add origin https://github.com/user/repo.git
# Registers a remote named "origin"

2 push, pull, fetch — what's the actual difference

git fetch origin
# Downloads new commits from the remote, but does NOT merge them into your branch

git merge origin/master
# The second half: merges what you just fetched into your current branch

git pull
# Shorthand for fetch + merge in one step (this is the one most people use daily)

git push origin feature-login
# Uploads your branch's new commits to the remote
💡 git pull is convenient but hides what's happening. When something feels confusing after a pull, fetch then log to see exactly what came down before merging.

3 Tracking branches

When you push a new branch for the first time, you link your local branch to its remote counterpart with -u (upstream). After that, plain git push/git pull know where to go automatically.

git push -u origin feature-login
# First push: sets up tracking. After this, just "git push" works.

git branch -vv
# Shows each local branch and which remote branch it tracks, plus ahead/behind count
