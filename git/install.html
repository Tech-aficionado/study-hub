⚙️ Install & First-time Config Beginner

Five minutes of one-time setup so every repository you ever touch behaves correctly — especially on Windows.

1 Installing Git

Git is a single small program you install once per machine. How you get it depends on your operating system:

# Windows — download the installer from git-scm.com, or:
winget install --id Git.Git -e

# macOS — Homebrew (or Xcode Command Line Tools)
brew install git

# Debian / Ubuntu
sudo apt install git

# Fedora
sudo dnf install git

# Confirm it worked — prints something like "git version 2.47.0"
git --version
💡 On Windows the official installer bundles Git Bash, a small Unix-style shell. Many Git tutorials assume a Bash-like shell, so Git Bash is the friendliest place to follow along even though Git works fine from PowerShell and CMD too.

2 Identity — who made each commit

Every commit records a name and email. Git refuses to let you commit until you set them. These are not login credentials — they are just stamped onto your commits as the author, so set them once, globally, right after installing.

git config --global user.name "Ada Lovelace"
git config --global user.email "ada@example.com"

# See everything Git currently has configured, and WHERE each value came from
git config --list --show-origin
The --global flag writes to ~/.gitconfig, applying to every repo for your user. Drop --global inside a repo to override just that one repo (handy for a work email on work projects).

3 Default branch name

Historically git init created a branch called master. Modern Git lets you choose the default; most hosting platforms and new projects now use main.

git config --global init.defaultBranch main
# New repos created with "git init" now start on a branch called "main"

4 Your default editor

Some Git operations (writing a commit message without -m, an interactive rebase) open a text editor. If you don't set one, Git may drop you into Vim, which surprises a lot of beginners.

# VS Code (the --wait is important — Git waits for you to close the tab)
git config --global core.editor "code --wait"

# Nano, if you prefer a simpler terminal editor
git config --global core.editor "nano"
💡 Stuck in Vim with no idea how to leave? Press Esc, then type :wq and Enter to save and quit, or :q! to quit without saving.

5 Line endings — the #1 Windows gotcha

Windows ends lines with two characters (CRLF, carriage-return + line-feed); macOS and Linux use one (LF). If a Windows and a Mac developer edit the same file, Git can show the entire file as changed just because of invisible line-ending differences. The core.autocrlf setting fixes this.

# Windows: store LF in the repo, convert to CRLF when checking out
git config --global core.autocrlf true

# macOS / Linux: convert any accidental CRLF to LF on commit
git config --global core.autocrlf input
⚠️ A warning like LF will be replaced by CRLF the next time Git touches it is informational, not an error — it's Git telling you it's normalising line endings per your setting. The more robust, team-wide fix is a committed .gitattributes file (covered on its own page) so the behaviour doesn't depend on each person's local config.

6 Helpful quality-of-life defaults

# Colourful output in the terminal
git config --global color.ui auto

# On "git pull", rebase instead of creating a merge commit (cleaner history)
git config --global pull.rebase true

# Remember your HTTPS credentials so you don't retype them every push
git config --global credential.helper manager   # Windows

# Make "git br / git co / git st" shortcuts
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.st status
git config --global alias.lg "log --oneline --graph --all"
Aliases are pure convenience — git lg now runs your favourite log view. They live in your .gitconfig and never affect the repository itself.
