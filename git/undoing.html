↩️ Undoing Mistakes Intermediate

reset, revert, checkout, stash, reflog — know which one is safe and which one rewrites history.

1 Unstaging and discarding — before you commit

git restore --staged file.txt
# Unstages a file (keeps your edits, just removes it from "next commit")

git restore file.txt
# ⚠️ DISCARDS uncommitted changes to this file — permanent, no undo
🛑 git restore file.txt (and the older git checkout -- file.txt) permanently throws away uncommitted edits. There is no recovering them — Git never tracked them in the first place.

2 git revert — the SAFE undo for shared history

git revert creates a NEW commit that undoes a previous one. History isn't rewritten — the "bad" commit is still there, plus a new commit cancelling it out. This is safe to use on a branch others are already working from.

git revert <commit-hash>
# Creates a new commit that undoes the changes from that commit

3 git reset — the DANGEROUS undo that rewrites history

git reset moves your branch pointer backward. Depending on the flag, it also changes your staging area and working files. Never use reset on commits you've already pushed and shared — use revert instead.

CommandWhat movesRisk
git reset --soft HEAD~1Branch pointer onlyLow — your changes stay staged
git reset --mixed HEAD~1Pointer + staging areaMedium — changes unstaged, but kept in your files
git reset --hard HEAD~1Pointer + staging + working files🛑 High — your actual file edits are GONE
🛑 git reset --hard permanently discards uncommitted work in your files. There is no confirmation prompt. Double-check git status before running it.

4 git stash — a shelf for unfinished work

Need to switch branches but your current changes aren't ready to commit? Stash tucks them away temporarily.

git stash
# Saves uncommitted changes, resets your working directory to clean

git stash list
git stash pop
# Reapplies the most recent stash and removes it from the stash list

git stash apply
# Reapplies but KEEPS it in the stash list (useful to apply to multiple branches)

5 git reflog — your safety net

Git almost never truly deletes a commit immediately. reflog is a log of everywhere HEAD has pointed recently — including commits a reset --hard seemed to "lose." This has rescued countless people from a bad reset.

git reflog
# Shows recent HEAD movements with their commit hashes

git reset --hard <hash-from-reflog>
# Recovers to that exact point
💡 If you ever "lose" commits after a reset, don't panic — run git reflog first. The commit is very likely still there, just not pointed to by any branch.
