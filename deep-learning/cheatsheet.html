3 Optimizer comparison

OptimizerCore ideaProsCons
SGDStep opposite the gradient of a mini-batch, scaled by a fixed learning rate (optionally + momentum)Simple, well understood, can generalize very well when tunedSensitive to learning rate choice; can be slow to converge
RMSpropDivides the learning rate by a running average of recent squared gradients, per parameterAdapts step size per parameter; handles noisy/non-stationary objectives wellStill needs a reasonable base learning rate; fewer theoretical guarantees
AdamCombines momentum (running average of gradients) with RMSprop-style per-parameter scalingFast convergence, robust default, minimal tuning neededCan generalize slightly worse than well-tuned SGD on some tasks; more memory (tracks 2 moments per parameter)

4 CNN quick facts

  • Convolutional layers use weight sharing — one filter's weights are reused across the whole spatial input.
  • Max pooling downsamples and adds translation invariance; it has no learnable parameters.
  • Stride controls how far a filter moves per step; padding controls output size at the borders.
  • Feature maps grow in semantic depth but shrink in spatial size as you go deeper.
  • Transfer learning: freeze early layers (general features), fine-tune later layers (task-specific features).

5 RNN / LSTM / GRU quick facts

  • An RNN reuses the same weights at every time step, driven by a running hidden state.
  • Backpropagation through time (BPTT) = unroll the RNN across time steps, then backprop normally.
  • Plain RNNs suffer vanishing gradients over long sequences.
  • LSTM: 3 gates (forget, input, output) + a separate cell state → strong long-range memory.
  • GRU: 2 gates (update, reset), no separate cell state → fewer params, faster, comparable accuracy.
  • Transformers replace recurrence with self-attention, enabling full parallelization across the sequence.
