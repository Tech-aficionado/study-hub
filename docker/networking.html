🌐 Networking Intermediate

How containers find each other, and how the outside world finds them.

1 How containers find each other — in plain English

Install Docker, and it quietly builds something called docker0 — think of it as an invisible network switch living inside your computer. Every container you start plugs into that switch automatically and gets handed a private internal IP address, the same way your router hands out IPs on your home WiFi. That's the default bridge network, and it "just works" without you doing anything.

DriverWhat it actually does
bridge (default)The private internal switch — containers get their own IP and can reach each other
hostNo isolation at all — the container just borrows the host's own network directly
noneCompletely cut off — no networking, period
overlayStretches a network across multiple physical machines (used by Swarm/clusters)

2 Build your own "walled garden" + call containers by name

The default bridge works, but it's messy — everything on it can see everything else. The better habit is to create your own network and only put related containers on it, like building a private walled garden where only your app's pieces can talk to each other. Containers outside that network can't reach in.

The nice bonus: on a custom network, Docker runs its own internal DNS, so a container can reach another one just by its name — no need to track changing IP addresses. If your API container needs the database, it just connects to the hostname db, and Docker quietly resolves that to the right IP.

# create your own private network ("walled garden")
docker network create mynet

# put containers inside it with --network
docker run -d --name db --network mynet postgres
docker run -d --name api --network mynet myapi

# inside the "api" container, you can now just do: ping db
# — no IP address needed, Docker's DNS resolves the name

docker network ls                        # see all networks
docker network inspect mynet             # who's connected?
docker network connect mynet some_container
docker network rm mynet

3 Letting the outside world in: port publishing

Even once your app is running inside a container, your browser on the host machine still can't reach it until you explicitly open a door. That's what -p does — it punches a hole from a port on your real machine straight through to a port inside the container.

docker run -p 8080:80 nginx              # your machine's 8080 → container's 80
docker run -p 127.0.0.1:8080:80 nginx    # only reachable from this machine, not the network
docker run -P nginx                      # publish every EXPOSEd port to a random free host port
The format is always HOST_PORT:CONTAINER_PORT — left side is your real machine, right side is inside the box. Flipping these two around by mistake is the single most common "why can't I open my app" bug.
