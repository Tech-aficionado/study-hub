🏭 Multi-stage Builds Advanced

Keep build tools out of your production image.

1 The problem: your production image carries build tools it doesn't need

Compiling code — say, a Go binary or a React app — needs a whole toolchain: compilers, package managers, source files. None of that is needed once the compiled result exists. If you build and run in the same stage, your final image ships that entire toolchain anyway, bloating it by hundreds of megabytes for no reason. Multi-stage builds fix this: one stage does the heavy building, and you copy only the finished result into a second, much leaner stage that's what actually ships.

2 Example: Go binary

# Stage 1: build
FROM golang:1.22 AS builder
WORKDIR /src
COPY . .
RUN CGO_ENABLED=0 go build -o /app/server .

# Stage 2: minimal runtime (final image)
FROM alpine:3.19
COPY --from=builder /app/server /usr/local/bin/server
ENTRYPOINT ["server"]
Result: a ~15MB final image instead of a 1GB+ image carrying the entire Go toolchain.

3 Example: React/Node frontend

FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:1.27-alpine
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
