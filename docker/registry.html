☁️ Registries & Docker Hub Intermediate

Storing and distributing your images.

1 Pushing your own image to the world

Building an image on your laptop is only useful to you. To let a server, a teammate, or a CI pipeline pull it down, you push it to a registry — the same way a Dockerfile builds an image, a registry is just storage for images, with Docker Hub being the default public one.

docker login
docker tag myapp:1.0 yourusername/myapp:1.0
docker push yourusername/myapp:1.0
docker pull yourusername/myapp:1.0

2 Common registries

RegistryNotes
Docker HubDefault public registry; free tier has pull-rate limits
GitHub Container Registry (ghcr.io)Tied to GitHub repos/orgs, great for CI
AWS ECRPrivate registry integrated with IAM/ECS/EKS
Self-hosted (registry:2)Run your own with the official registry image
⚠️ Never bake secrets/API keys into an image — anyone who can pull the image can recover them. Values passed via ENV/ARG show up in docker history, and copied-in files can be pulled straight out of the layers with docker save — even if a later step deletes them. Use BuildKit build secrets (RUN --mount=type=secret) or inject them at runtime instead.
