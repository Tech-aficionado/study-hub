🏗️ buildx, Multi-platform & docker init Advanced

The modern build engine — one image that runs on your Mac's ARM chip and the cloud's x86 servers, and a one-command way to scaffold Docker files.

1 BuildKit: the engine behind modern builds

Every recent Docker build is powered by BuildKit — the rebuilt build backend that replaced the old sequential builder. You usually don't call it directly; docker build uses it. What it buys you:

  • Parallelism — independent build stages run at the same time, not one after another.
  • Smarter caching — fine-grained, and shareable to a registry so CI runners reuse each other's cache.
  • Mounts in RUN — RUN --mount=type=cache keeps a package cache between builds; RUN --mount=type=secret exposes a secret for one step without baking it into a layer.
# cache the npm download dir across builds — much faster re-installs
RUN --mount=type=cache,target=/root/.npm npm ci

2 buildx — the extended CLI

docker buildx is the front-end that exposes BuildKit's full power, most importantly building for CPU architectures other than your own. You work through a builder instance:

docker buildx create --name mybuilder --use   # create & select a builder
docker buildx inspect --bootstrap             # start it, show capabilities
docker buildx ls                              # list builders and their platforms

3 Why multi-platform matters — the Apple Silicon problem

Here's the pain it solves. You develop on an Apple Silicon Mac — an arm64 chip. You build an image, it works locally, you push it, and it crashes on your cloud servers because they're amd64 (x86). The image only contained ARM binaries. Before multi-platform builds, you had to maintain two pipelines.

A multi-platform image fixes this: one tag that bundles variants for several architectures behind a manifest list. Whoever pulls it automatically gets the one matching their machine.

# build BOTH architectures and push the manifest list in one go
docker buildx build --platform linux/amd64,linux/arm64 \
  -t username/myapp:1.0 --push .
⚠️ Multi-platform builds can't just load into the local image store (which holds one architecture). Use --push to send straight to a registry, or --load for a single platform. Building a foreign arch uses QEMU emulation and is slower than native.

4 docker init — scaffold Docker files in one command

Starting from an un-containerised project? docker init is an interactive wizard that detects your language/framework and writes sensible starter files so you don't hand-craft boilerplate.

cd my-project
docker init
# answers a few prompts, then generates:
#   Dockerfile          (multi-stage, non-root user, slim base)
#   .dockerignore
#   compose.yaml
#   README.Docker.md

Treat the output as a well-reasoned starting point: it already applies good defaults (a multi-stage build, a non-root USER, a pinned slim base image), which you then tune for your app. It's the fastest honest way to go from "my code" to "a container that builds".

💡 Great for learning too — run it on a small app and read the generated Dockerfile to see how Docker itself recommends structuring one for your stack.
