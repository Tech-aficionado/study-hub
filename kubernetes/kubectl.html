⌨️ kubectl & kubeconfig Beginner → Intermediate

kubectl is just an HTTP client for the API server — once you see that, every command makes sense.

1 The shape of every kubectl command

Almost every command is kubectl <verb> <resource> [name] [flags]. Learn a handful of verbs and they combine with every resource type.

kubectl get pods                 # list
kubectl get pod my-pod -o yaml   # one object, full YAML
kubectl describe pod my-pod      # human-readable detail + Events
kubectl create -f app.yaml       # error if it already exists
kubectl apply -f app.yaml        # create OR update (declarative)
kubectl delete -f app.yaml
kubectl edit deployment my-app   # open in $EDITOR, applied on save
💡 apply vs create: create is imperative ("make this now, fail if it exists"); apply is declarative ("make reality match this file") and is what you use in GitOps and CI. Prefer apply for anything you keep in version control.

2 Output and filtering flags you'll use daily

FlagDoes
-o wideExtra columns (node, IP) in the table
-o yaml / -o jsonFull object as YAML/JSON
-o jsonpath='{.items[*].metadata.name}'Pull out specific fields for scripts
-A / --all-namespacesAcross every namespace
-n <ns>Target one namespace

--show-labelsShow each object's labels
-w / --watchStream changes live

3 kubeconfig — how kubectl knows which cluster

kubectl reads ~/.kube/config (override with $KUBECONFIG). That file holds three lists and a pointer:

  • clusters — API server URLs + their CA certs.
  • users — your credentials (client cert, token, or an exec plugin for cloud auth).
  • contexts — each one pairs a cluster + a user + a default namespace.
  • current-context — the single pointer that decides where the next command goes.

4 Switching clusters and namespaces

kubectl config get-contexts            # list; * marks current
kubectl config current-context
kubectl config use-context kind-dev    # switch cluster
kubectl config set-context --current --namespace=staging
# point at a different kubeconfig for one command:
KUBECONFIG=~/work/prod.yaml kubectl get pods
⚠️ The classic incident: you ran a command against prod because the current-context was still prod from an hour ago. Check kubectl config current-context before anything destructive, and consider a shell prompt plugin (kube-ps1) that shows the context/namespace at all times.

5 Debug & introspection commands

kubectl logs my-pod                    # container logs
kubectl logs my-pod -c sidecar --previous  # a specific container, previous crash
kubectl logs -f -l app=web             # follow logs across all matching Pods
kubectl exec -it my-pod -- sh          # shell inside the Pod
kubectl port-forward svc/my-svc 8080:80
kubectl cp my-pod:/var/log/app.log ./app.log
kubectl explain deployment.spec.strategy   # field docs, offline
kubectl api-resources                  # every resource type + its short name
💡 kubectl explain <resource>.<field> is a built-in, always-current schema reference — faster than opening the website when you forget a field name.
