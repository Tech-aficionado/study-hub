🏛️ Architecture Beginner

A cluster is a Control Plane plus a fleet of Worker Nodes — here's who does what.

1 The two halves of a cluster

2 Control Plane components — the "brain"

  • API Server — the single front door. kubectl and every other component talk to the cluster ONLY through this.
  • etcd — a distributed key-value store holding the entire cluster's state (what SHOULD be running, where). This is the single source of truth.
  • Scheduler — when a new Pod needs to run, decides WHICH worker node has room/resources for it.
  • Controller Manager — runs the background loops that constantly reconcile actual state with desired state (the self-healing logic).

3 Worker Node components — where your app actually runs

  • kubelet — the agent on each node that talks to the API Server and makes sure the containers it's told to run are actually running.
  • Container runtime — the actual engine pulling images and starting containers (containerd, CRI-O).
  • kube-proxy — maintains network rules so traffic reaches the right Pods.
