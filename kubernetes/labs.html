🧪 Labs Hands-on

Run these on a local cluster (see Local setup) or dry-run the ideas in the Playground. Each lab has a goal, steps, and a "you've done it when" check.

1 Lab 1 — Deploy, expose, scale

Goal: get an app running and reachable, then scale it.

kubectl create deployment web --image=nginx --replicas=3
kubectl expose deployment web --port=80 --type=NodePort
kubectl get pods,svc -o wide
kubectl scale deployment web --replicas=5
kubectl port-forward deployment/web 8080:80
# curl http://localhost:8080 in another terminal
✅ Done when: 5 Pods are Running, the Service lists 5 endpoints (kubectl describe svc web), and curl returns the nginx page.

2 Lab 2 — Rolling update & rollback

Goal: ship a new version with zero downtime, then undo it.

kubectl set image deployment/web nginx=nginx:1.27
kubectl annotate deployment/web kubernetes.io/change-cause="to 1.27"
kubectl rollout status deployment/web
kubectl rollout history deployment/web
kubectl rollout undo deployment/web
kubectl get rs       # see old + new ReplicaSets
✅ Done when: history shows ≥ 2 revisions with CHANGE-CAUSE, and after undo the previous ReplicaSet is scaled back up.

3 Lab 3 — Config, Secrets, probes

Goal: inject config and a secret, and add a readiness probe.

kubectl create configmap web-config --from-literal=GREETING=hello
kubectl create secret generic web-secret --from-literal=TOKEN=abc123
# edit the Deployment: envFrom configMapRef + secretRef, and a readinessProbe
kubectl edit deployment web
kubectl exec deploy/web -- printenv GREETING TOKEN
✅ Done when: printenv shows both values, and a Pod only joins the Service's endpoints once its readiness probe passes.

4 Lab 4 — Break it on purpose (troubleshooting)

Goal: reproduce each failure and diagnose it with the runbook.

  • ImagePullBackOff: kubectl set image deployment/web nginx=nginx:doesnotexist → describe → read the Event.
  • CrashLoopBackOff: run a container whose command is sh -c 'exit 1' → logs --previous.
  • Pending: request cpu: "100" → describe → FailedScheduling.
  • No endpoints: change the Service selector to a label no Pod has → describe svc shows empty Endpoints.
✅ Done when: for each break you can state the Event/exit code that revealed the cause before fixing it.

5 Lab 5 — Persistent state & a Job

Goal: use a PVC and run a one-off Job.

# create a PVC (uses the default StorageClass), mount it in a Pod, write a file,
# delete the Pod, recreate it, confirm the file is still there.
kubectl apply -f pvc.yaml
# then run a Job and read its logs
kubectl create job hello --image=busybox:1.36 -- /bin/sh -c 'echo done; sleep 2'
kubectl get jobs
kubectl logs job/hello
✅ Done when: the file written to the PVC survives Pod deletion/recreation, and the Job reaches Complete with your output in its logs.
