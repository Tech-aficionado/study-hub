💻 Local setup Beginner

You don't need a cloud account to learn Kubernetes — spin up a real cluster on your laptop in one command.

1 Why a local cluster

A local, single-machine cluster behaves like the real thing: same API, same kubectl, same YAML. It is free, disposable (delete and recreate in seconds), and offline-friendly. The four common options differ mostly in how heavy they are and whether they run multiple nodes.

2 kind — Kubernetes IN Docker

kind runs each cluster node as a Docker container. It is the lightest way to get a genuine multi-node cluster and is what the Kubernetes project itself uses for CI.

# install (macOS/Linux) then:
kind create cluster --name dev
kubectl cluster-info --context kind-dev
kind get clusters
kind delete cluster --name dev

A multi-node cluster from a config file:

# kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
  - role: control-plane
  - role: worker
  - role: worker
kind create cluster --config kind-config.yaml

3 minikube — the beginner-friendly all-rounder

minikube spins up a single-node cluster in a VM or container and ships a batch of one-command addons (dashboard, ingress, metrics-server) that are fiddly to install by hand elsewhere.

minikube start
minikube status
minikube addons enable ingress
minikube addons enable metrics-server
minikube dashboard          # opens the web UI
minikube service my-svc     # opens a NodePort/LB service in the browser
minikube stop
minikube delete
💡 minikube image load myapp:1.0 pushes a locally-built image straight into the cluster so you don't need a registry while developing.

4 k3d — k3s in Docker, very fast

k3d wraps k3s (Rancher's lightweight, <100MB Kubernetes distribution) in Docker. It starts in a few seconds and uses little memory — great on a modest laptop.

k3d cluster create dev --agents 2
k3d cluster list
k3d cluster delete dev

5 Docker Desktop — the zero-install option

If you already run Docker Desktop, enable Kubernetes in Settings → Kubernetes → Enable Kubernetes. It installs a single-node cluster and sets up a docker-desktop kubectl context automatically. No multi-node, but perfect for quick checks.

kubectl config use-context docker-desktop
kubectl get nodes

6 First smoke test — the same on every tool

kubectl create deployment hello --image=nginx --replicas=2
kubectl expose deployment hello --port=80 --type=NodePort
kubectl get pods,svc
kubectl port-forward deployment/hello 8080:80
# now curl http://localhost:8080
⚠️ A fresh cluster has no LoadBalancer provider, so a type: LoadBalancer Service stays <pending> for its external IP. Use NodePort, port-forward, or minikube's tunnel locally.
