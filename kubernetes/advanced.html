1 Can you explain each of these in one breath?

  • Namespaces, ResourceQuota, LimitRange → multi-tenancy: isolate, cap totals, set per-Pod defaults. Deep dive →
  • Scheduling → nodeSelector/affinity (Pod attracts), taints/tolerations (node repels), spread constraints, PriorityClass. Deep dive →
  • Autoscaling → HPA (more Pods), VPA (bigger Pods), Cluster Autoscaler (more nodes); all need metrics. Deep dive →
  • Resources & QoS → requests schedule, limits cap; CPU throttles, memory OOMKills; Guaranteed/Burstable/BestEffort. Deep dive →
  • Probes → liveness restarts, readiness de-routes, startup gates. Deep dive →

2 Security surface

  • RBAC & ServiceAccounts → Role/ClusterRole + bindings; Pods authenticate as ServiceAccounts; least privilege. Deep dive →
  • Pod security → securityContext hardening, Pod Security Admission (baseline/restricted), NetworkPolicy default-deny. Deep dive →
💡 "4 C's": Cloud → Cluster (RBAC, NetworkPolicy) → Container (securityContext, PSA) → Code. Each layer protects the one inside it.

4 Packaging & delivery

  • Helm → templated charts, releases with history, upgrade --install, Helm 3 is clientless. Deep dive →
  • Kustomize → template-free overlays, built into kubectl apply -k.
  • GitOps (Argo CD / Flux) → Git is the source of truth; a controller reconciles the cluster to match the repo.
