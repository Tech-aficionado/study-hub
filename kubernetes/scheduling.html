🧭 Scheduling & affinity Advanced

How to influence WHERE a Pod lands — from a blunt label match to repelling Pods off reserved nodes.

1 nodeSelector — the simplest constraint

A hard requirement: only schedule onto nodes carrying these labels. Blunt but clear.

kubectl label node node-1 disktype=ssd
# in the Pod spec:
spec:
  nodeSelector:
    disktype: ssd

nodeName (pin to one exact node) exists too but bypasses the scheduler entirely — avoid it outside debugging.

2 Node affinity — nodeSelector with nuance

Affinity adds soft preferences and richer operators:

  • requiredDuringScheduling... — hard rule (like nodeSelector, but with In/NotIn/Exists).
  • preferredDuringScheduling... — soft; the scheduler weights it but will still place the Pod if unmet.
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
        - matchExpressions:
            - { key: topology.kubernetes.io/zone, operator: In, values: [us-east-1a, us-east-1b] }
    preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 50
        preference:
          matchExpressions:
            - { key: disktype, operator: In, values: [ssd] }

"IgnoredDuringExecution" means the rule is only checked at scheduling time — a label change later won't evict a running Pod.

3 Pod affinity / anti-affinity & spreading

  • podAffinity — place this Pod near Pods matching a label (e.g. co-locate a cache with its app on the same node/zone).
  • podAntiAffinity — keep it away from matching Pods (e.g. spread replicas across nodes so one node's failure doesn't take them all).
  • topologySpreadConstraints — the modern, cleaner way to spread Pods evenly across zones/nodes with a maxSkew.
topologySpreadConstraints:
  - maxSkew: 1
    topologyKey: topology.kubernetes.io/zone
    whenUnsatisfiable: DoNotSchedule
    labelSelector: { matchLabels: { app: web } }

4 Taints & tolerations — repelling, not attracting

Affinity is a Pod choosing nodes. Taints are a node repelling Pods: a taint on a node says "don't schedule here unless you explicitly tolerate this". Used to reserve nodes (GPU, control-plane, dedicated tenants).

kubectl taint nodes gpu-1 gpu=true:NoSchedule

Only Pods with a matching toleration can then land there (tolerating isn't the same as requiring — pair with nodeSelector/affinity to actively target the node):

tolerations:
  - key: gpu
    operator: Equal
    value: "true"
    effect: NoSchedule
Taint effectDoes
NoScheduleNew Pods without a toleration won't be scheduled here
PreferNoScheduleSoft — avoid if possible
NoExecuteAlso evicts already-running Pods that don't tolerate it
💡 Mental model: affinity = Pod attraction to nodes; taints/tolerations = node repulsion of Pods. Control-plane nodes are tainted so your workloads don't land on them; node-level agents (DaemonSets) carry tolerations so they can.

5 PriorityClass & preemption

A PriorityClass gives Pods a priority value. When the cluster is full and a high-priority Pod can't schedule, the scheduler may preempt (evict) lower-priority Pods to make room. Use it to guarantee critical workloads win under contention — and set a sensible default so routine Pods don't accidentally outrank system ones.
