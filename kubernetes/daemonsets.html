🛰️ DaemonSets Advanced

"Run exactly one copy of this Pod on every node" — for node-level agents.

1 One Pod per node, automatically

A DaemonSet ensures a copy of a Pod runs on each (matching) node. When a node joins the cluster, its DaemonSet Pod is added automatically; when a node leaves, that Pod is garbage-collected. You don't set a replica count — the count is the number of nodes.

2 What runs as a DaemonSet

  • Log collectors — Fluent Bit / Fluentd / Vector, reading every node's container logs.
  • Node monitoring — Prometheus node-exporter, metrics agents.
  • Networking — CNI plugins (Calico, Cilium) and kube-proxy itself run as DaemonSets.
  • Storage — CSI node drivers.
apiVersion: apps/v1
kind: DaemonSet
metadata: { name: node-exporter }
spec:
  selector: { matchLabels: { app: node-exporter } }
  template:
    metadata: { labels: { app: node-exporter } }
    spec:
      containers:
        - name: node-exporter
          image: prom/node-exporter:v1.8.2

3 Targeting a subset of nodes, and reaching tainted nodes

Add a nodeSelector or affinity to the template to run only on some nodes (e.g. only GPU nodes). To run on control-plane or otherwise tainted nodes — common for logging/monitoring that must cover every node — add matching tolerations:

spec:
  template:
    spec:
      nodeSelector: { gpu: "true" }
      tolerations:
        - key: node-role.kubernetes.io/control-plane
          operator: Exists
          effect: NoSchedule
💡 DaemonSets have their own rolling-update strategy (updateStrategy: RollingUpdate with maxUnavailable) so an agent upgrade rolls node by node rather than restarting everywhere at once.
