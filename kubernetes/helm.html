⎈ Helm Advanced

The package manager for Kubernetes — template your manifests once, install them anywhere with different values.

1 Why Helm exists

Raw YAML gets repetitive and un-reusable fast: the same app for dev/staging/prod means three near-identical manifest sets differing only in replica counts, image tags, and hostnames. Helm packages manifests into a reusable, templated Chart with a values.yaml you override per environment — install the whole app in one command.

2 Chart, Release, Repository, Values

  • Chart — the package: templated manifests + default values + metadata.
  • Release — an installed instance of a chart in a cluster (named), with its own revision history.
  • Repository — where charts are hosted (an HTTP index, or an OCI registry).
  • Values — the parameters that fill the templates; defaults in values.yaml, overridden with --set or -f my-values.yaml.
my-chart/
├── Chart.yaml          # name, version, appVersion
├── values.yaml         # default values
└── templates/
    ├── deployment.yaml # {{ .Values.replicaCount }} etc.
    ├── service.yaml
    └── _helpers.tpl    # reusable template snippets

3 Everyday commands

helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update
helm search repo nginx
helm install web bitnami/nginx --set replicaCount=3
helm upgrade web bitnami/nginx -f prod-values.yaml
helm upgrade --install web ./my-chart     # install or upgrade in one
helm list
helm history web
helm rollback web 2
helm uninstall web

Dry-run and render before you apply:

helm template web ./my-chart -f prod-values.yaml   # render to stdout, no cluster
helm install web ./my-chart --dry-run --debug      # server-side dry run
helm lint ./my-chart

4 Templating & the gotchas

Templates use Go templating with Sprig functions: {{ .Values.x }}, {{ .Release.Name }}, conditionals ({{ if }}), loops ({{ range }}), and helpers in _helpers.tpl.

spec:
  replicas: {{ .Values.replicaCount | default 1 }}
  template:
    spec:
      containers:
        - name: {{ .Chart.Name }}
          image: "{{ .Values.image.repo }}:{{ .Values.image.tag }}"
💡 Helm 3 removed the server-side Tiller component (the big security complaint about Helm 2) — Helm 3 is a client-only tool that stores release state as Secrets in the cluster. If an interviewer mentions Tiller, "that's Helm 2; Helm 3 is clientless" is the answer.
⚠️ Helm renders text templates, so YAML indentation inside templates is fragile — a mis-indented {{ toYaml }} breaks the manifest. Use nindent/indent and always helm template to inspect the rendered output before shipping. Alternatives worth naming: Kustomize (template-free overlays, built into kubectl) and Argo CD (GitOps delivery, often wrapping Helm/Kustomize).
