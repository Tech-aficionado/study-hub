🖥️ Virtualization for Cloud Intermediate

Why the cloud needs virtualization, the VM taxonomy, and the hypervisors that run production clouds.

1 Why cloud computing needs virtualization

A single physical server has fixed CPU, RAM and disk. Without virtualization, one customer's workload would occupy the whole machine, wasting most of its capacity most of the time. Virtualization inserts a software layer that lets one physical machine pretend to be many independent machines (virtual machines), each isolated from the others, so a provider can safely run many customers' workloads on the same hardware — this multi-tenancy is exactly what makes cloud economics work.

2 Pros and cons

Pros

  • High hardware utilization via multi-tenancy
  • Strong isolation between workloads
  • Fast provisioning — a new VM in seconds/minutes, not a hardware order
  • Live migration — move a running VM between hosts with near-zero downtime
  • Snapshotting/rollback for easy recovery

Cons

  • Performance overhead versus bare metal (hypervisor tax)
  • Added management complexity (another layer to patch and secure)
  • "Noisy neighbor" risk if resource limits aren't enforced well
  • Licensing costs for some commercial hypervisors

4 The Virtual Machine Monitor (VMM) / Hypervisor

The Virtual Machine Monitor (VMM), also called a hypervisor, is the software layer that creates and manages VMs, multiplexing physical CPU, memory, storage and I/O among them. Key properties a VMM must provide:

  • Equivalence/fidelity — software inside the VM runs essentially identically to running on real hardware.
  • Resource control — the VMM has complete control over physical resources; a guest cannot access resources not explicitly allocated to it.
  • Efficiency — most instructions run directly on the hardware with no VMM intervention, so performance overhead stays low.

5 Interpretation vs binary translation vs HLL VMs

  • Interpretation — each guest instruction is fetched, decoded and emulated one at a time by software. Simple to build, portable, but slow (every instruction pays interpretation overhead).
  • Binary translation — guest instructions are translated (often just-in-time, and cached) into equivalent host instructions ahead of execution, trading some upfront translation cost for much faster repeated execution.
  • High-Level-Language VM (HLL VM) — doesn't virtualize an ISA at all; instead it defines its own abstract bytecode and instruction set above any specific hardware (e.g. JVM bytecode, .NET CIL), giving "write once, run anywhere" portability as a Process VM.
