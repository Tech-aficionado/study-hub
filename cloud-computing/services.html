🧩 Cloud Services Beginner

Service models (SaaS, PaaS, IaaS, DaaS and more), providers, deployment models, advantages and risks.

1 The core service models

ModelWhat the provider managesWhat you manageExample
IaaS — Infrastructure as a ServicePhysical hardware, virtualization, networking, storageOS, runtime, apps, dataAWS EC2, Azure VMs, Google Compute Engine
PaaS — Platform as a ServiceInfrastructure + OS + runtimeYour application code and dataGoogle App Engine, Azure App Service, Heroku
SaaS — Software as a ServiceEverything — infrastructure through the application itselfJust your data and configurationSalesforce, Gmail, Microsoft 365
DaaS — Desktop as a ServiceVirtual desktop infrastructure, patching, backupsUser profile/apps on the virtual desktopAmazon WorkSpaces, Windows 365
💡 Pizza analogy: IaaS is buying raw ingredients and using your own oven (you cook). PaaS is ordering a pizza kit delivered to your door. SaaS is ordering a pizza to be delivered, ready to eat.

2 Supporting "as a Service" categories

  • MaaS — Monitoring as a Service: outsourced monitoring of infrastructure, application performance, uptime and security events, usually with dashboards and alerting (e.g. Datadog, New Relic).
  • CaaS — Communication as a Service: outsourced enterprise communication — VoIP, messaging, video conferencing, unified communications — delivered over the cloud instead of on-prem PBX hardware (e.g. Zoom, RingCentral, Twilio).
  • CaaS — Containers as a Service (not to be confused with the above): managed container orchestration, e.g. Amazon ECS/EKS, Azure Kubernetes Service.
  • FaaS — Functions/Serverless: run individual functions on demand with no server management at all, billed per invocation (AWS Lambda, Azure Functions).

4 Deployment models

PrivateDedicated infrastructure for a single organization, on-prem or hosted

HybridCombination of two or more models, with workloads able to move between them

5 Advantages

  • No capital expense on hardware — convert CapEx into predictable OpEx.
  • Elastic, on-demand scaling that matches real-time demand.
  • Provider-managed patching, redundancy and disaster recovery.
  • Global deployment in minutes instead of months of data-center buildout.
  • Access to specialized managed services (ML, analytics, IoT) without building them yourself.

6 Challenges and risks

  • Vendor lock-in — proprietary APIs and data formats make switching providers expensive.
  • Security & compliance — shared responsibility means you still own data classification, access control and regulatory compliance.
  • Downtime — outages at the provider level affect every dependent customer simultaneously.
  • Cost unpredictability — pay-as-you-go billing can spike without strong governance and budgeting alerts.
  • Latency & data residency — physical distance to data centers and legal residency requirements can constrain architecture choices.
